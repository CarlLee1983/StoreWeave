# 65 — 退貨與換貨案件（RMA）

**What to build:** 為已出貨訂單建立可稽核的退貨／換貨案件，而不是改 Order 或 Shipment 狀態。
案件管理品項、數量、原因、物流回寄資訊、審核與收件結果，並在符合條件時請求既有退款流程。

**Blocked by:** 62, 63, 64

**Status:** ready-for-agent

- [ ] 顧客可對自己的符合資格訂單提出案件；後台可審核、要求補件、收件、拒絕或完成
- [ ] RMA 以訂單行與數量為基礎，避免同一數量重複退；第一版明定換貨是補寄或退款後重下單的策略
- [ ] 收到可回補庫存的退貨後才進行庫存調整；報廢／不可回補有明確原因與稽核
- [ ] 退款請求連結退款紀錄與 RMA；購物金、券與會員等級的部分退貨回沖另列決策，不得默默套用整單規則
- [ ] 補顧客授權、並發案件、部分數量、重送與作業流程 integration tests

## 不做的事

- 自動判定鑑賞期、爭議仲裁、逆物流最佳化與多包裹回寄。
