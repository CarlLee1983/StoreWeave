# 14 — 顧客註冊、登入與登出

**What to build:** 訪客可以用 email 與密碼註冊成為會員、登入、登出。顧客的領域資料有了落腳處，但生日、等級與點數等欄位在後續票才用得上。帳號與 session 沿用平台既有的那一套，不另寫一份密碼雜湊。

**Blocked by:** 11

**Status:** done

- [x] 訪客可註冊；重複的 email 在送出時回 409（**刻意不做送出前的可用性查詢**：那等於一條帳號枚舉管道，與 Spec 0001 對密碼重設要求的中性訊息自相矛盾）
- [x] 會員可登入取得 session、可主動登出
- [x] 顧客的領域資料屬於商務模組，平台的帳號模組不含任何顧客專屬欄位
- [x] 登入嘗試受到節流保護
- [x] 登入後的身分是顧客型別，稽核紀錄分得出來

使用者決定（2026-08-22）：顧客 session 30 天、後台維持 12 小時，TTL 進設定檔
（`auth.sessionTtlMinutes`）；顧客密碼下限 8 碼，後台維持 12 碼。

未包含（留給後續工單）：前台的註冊／登入 HTML 頁面。本票交付的是 API 與身分模型，
Theme 的頁面契約要動到 `StorefrontTheme`，與購物車頁（工單 29）一起做比較省。
