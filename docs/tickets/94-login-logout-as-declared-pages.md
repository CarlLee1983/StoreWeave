# 94 — 登入與登出走模組宣告的頁面

**What to build:** 使用者從前台表單登入、登入前放進購物車的東西跟著帶進來、按登出就回到首頁——這條路從此走模組宣告的頁面，而不是 controller 上的 decorator。新增一個由 release 組裝的認證模組，購物站先接上它。

順手兌現兩件契約上早就寫著、實作卻另有一套的事：登入後的轉址目的地由路由層統一清洗（只接受同源的站內路徑），以及已經登入的人打開登入頁會被帶回原本要去的地方，而不是又看到一次登入表單。

**Blocked by:** 93

**Status:** ready-for-agent

- [ ] 新增 `platform-auth` 模組，由 release 組裝；認證服務仍留在 `platform-identity`，identity 仍不宣告任何頁面
- [ ] 登入的 GET／POST 與登出的 POST 由模組宣告，controller 上對應的 decorator 刪除
- [ ] 登入成功簽發 Session、合併訪客購物車並帶出下架商品的提示；密碼錯誤回到登入頁且信箱欄位保留
- [ ] 已登入者打開登入頁被轉址，不再重新渲染表單（行為變更，要有測試指名它）
- [ ] 轉址只接受站內路徑，既有那組繞過寫法（`//`、反斜線、定位字元）全部仍被擋下
- [ ] 跨站送出的登入仍然 403；登入與登出的節流行為不變
- [ ] 前台登出對 CSRF header 的豁免從註解變成契約上看得見的宣告
- [ ] REST 的登入與登出行為完全不變
- [ ] 新套件的 importer 條目補進 lockfile（本地安裝不會自己補，Docker 的 frozen lockfile 才會炸）
- [ ] 因為模組數改變而失準的數字型斷言一併更新

## 邊界

忘記密碼與重設密碼這一票不動，仍留在 controller；`platform.auth` 系統頁因此還在，兩種形狀並存。
版型的拆分留到 98。
