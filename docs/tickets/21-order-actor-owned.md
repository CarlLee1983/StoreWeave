# 21 — 下單者由身分決定

**What to build:** 建立訂單不再接受自由填寫的 email 當作下單者 —— 下單者就是當下登入的顧客。未登入無法結帳。每一張訂單從此都有確定的歸屬。

**Blocked by:** 14

**Status:** done

- [x] 建立訂單的輸入不再包含下單者 email，下單者取自當下身分
- [x] 未登入或非顧客身分呼叫結帳被拒，錯誤訊息明確
- [x] 訂單與顧客之間有持久的關聯
- [x] 契約與事件的變更依既有的版本政策處理

一併做了前台的登入／註冊／登出頁（`StorefrontTheme.renderAuth`）。不做的話，結帳
需要身分等於把商店關掉——本票必須留下一個能用的產品，而不是一個「正確但沒人買得了」
的結帳流程。工單 11 的「checkout 維持強制匿名」在此被取代：CONTEXT.md 寫的是結帳
必須是已登入 Customer。

CSRF 改成 header 或表單隱藏欄位 `_csrf` 二擇一：伺服器渲染的表單送不出自訂 header，
把結帳排除在保護外不是選項。
