# 66 — 台灣電子發票 Provider 與帳務流程

**What to build:** 先確認商家採用的電子發票服務商與營運規則，再以 provider boundary 接入統編、
載具、捐贈、開立、作廢與折讓。付款、退款與發票各自的外部結果不可互相回滾。

**Blocked by:** 63

**Status:** ready-for-agent

- [ ] 在開發前記錄服務商、帳號／測試環境、開立時機、B2C／B2B 欄位、載具／捐贈與退款後處理規則
- [ ] 發票資料與訂單／退款關聯，有 provider reference、狀態、稅額、時間與稽核資料
- [ ] 在已確認的業務事件後非同步開立；失敗可重試並在後台可見，不能撤回已付款訂單
- [ ] 退款後依確認的 provider 規則執行作廢或折讓，重送 callback／job 不重複開立
- [ ] 顧客結帳與訂單頁只蒐集／顯示必要發票資訊；敏感資料受權限與日誌遮罩保護
- [ ] fake provider、自動化整合測試與服務商測試環境 UAT 都通過

## 不做的事

- 自建稅務規則引擎、會計總帳與跨國 VAT。
