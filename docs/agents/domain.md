# Domain docs

StoreWeave uses a single root context.

Before domain work, read the relevant terms in `CONTEXT.md` and the applicable decisions in `docs/adr/`. Read `docs/architecture.md` when tracing module boundaries. Use the glossary’s exact terms, including its _Avoid_ names, in issues, specs, code, and tests.

An ADR marked `proposed` is not an accepted decision. Surface any conflict with an accepted ADR explicitly.

If a relevant term or decision is missing, continue with the available evidence and record the gap for later domain-modeling work.
