## Seven required comparison cases

| Case | Exact upstream API / behaviour | Assessment for B00 |
| --- | --- | --- |
| 1. Drizzle transaction rollback / `db` adapter | Import `fromDrizzle` from `pg-boss` and `sql` from `drizzle-orm`, then call `boss.send(name, data, { db: fromDrizzle(tx, sql) })` inside `db.transaction(async tx => ...)`. The adapter needs the `sql` tag, supports node-postgres and postgres-js Drizzle drivers, and the docs state that pg-boss operations through it roll back with the ORM transaction. [official adapter docs](https://pgboss.io/api/adapters#drizzle), [rollback semantics](https://pgboss.io/api/adapters#rollback-behaviour), [adapter implementation](https://github.com/timgit/pg-boss/blob/12.30.0/src/adapters/drizzle.ts#L16-L45) | **Documented.** Required PoC: StoreWeave's actual Drizzle version/driver on PG17; insert domain test row + `send`, throw; assert neither survives; commit control case. The docs do not certify this repo's existing Drizzle `0.38.x` line. |
| 2. Dedupe returned identity | `send()` returns a newly created job id, but resolves **`null`** for opt-in unique/throttled non-inserts. `singletonSeconds`/`singletonKey` throttling accepts the first job and resolves `null` for later sends in that slot. `upsert(name, data, { singletonKey })` returns `{ jobs, updated, inserted }`, but updates/inserts only `created`/`retry` jobs; it is not a generic active-job dedupe identity API. [send result](https://pgboss.io/api/jobs#send), [throttle options](https://pgboss.io/api/jobs#send-name-data-options), [upsert contract](https://pgboss.io/api/jobs#upsertname-data-options) | **Documented mismatch / PoC required.** A contract requiring "same dedupe key returns the pre-existing job id" is not met by `send()`; test whether `upsert().jobs` supplies the desired pre-active identity and establish its concurrency behaviour. |
| 3. `replaceExisting` while running | There is **no documented `replaceExisting` option** in 12.30.0. `update()` and `upsert()` explicitly affect only `created`/`retry`; active, completed, and terminal jobs cannot be updated. Queue policies can constrain queued/active counts, but do not change that update restriction. [update contract](https://pgboss.io/api/jobs#updatename-data-options), [upsert contract](https://pgboss.io/api/jobs#upsertname-data-options), [queue policies](https://pgboss.io/api/queues#createqueuename-queue) | **Documented unsupported for an active replacement.** Required comparison PoC should demonstrate the exact active-job result, but pg-boss must not receive credit for an atomic `replaceExisting while running` contract without an adapter/design that preserves that contract. |
| 4. Crash / lease recovery | `expireInSeconds` defaults to 15 minutes and bounds how long an active attempt may remain active. Optional `heartbeatSeconds` (minimum 10) detects a dead worker; `work()` heartbeats automatically and a missing heartbeat causes fail/retry. Detection is `heartbeatSeconds` plus up to `monitorIntervalSeconds` (default 60). Both paths use normal retry rules. [queue heartbeat/expiration semantics](https://pgboss.io/api/queues#heartbeat-vs-expiration), [worker heartbeat behaviour](https://pgboss.io/api/workers#workname-options-handler), [job options](https://pgboss.io/api/jobs#send-name-data-options) | **Documented at-least-once recovery; fencing/late-owner outcome unverified.** Required PG17 PoC: claim, simulate loss/no heartbeat, run supervision, re-claim, then attempt old-worker completion and verify the old owner cannot overwrite the new attempt. Keep domain-side idempotency; the public API exposes no fencing token. |
| 5. DLQ retry / redrive | Configure `createQueue(source, { retryLimit, retryDelay, retryBackoff, deadLetter })`; after retries are exhausted, the payload is copied to the DLQ under the DLQ's configuration with `source*` provenance. `redrive(dlq, { destination?, sourceName?, limit? })` recreates jobs on their original source queue, but gives them a **new id**, reset retry count, cleared output, and destination queue defaults; it only moves pre-active DLQ jobs. A direct `retry(name, id)` retries a failed job in that queue. [DLQ configuration](https://pgboss.io/api/queues#createqueuename-queue), [redrive contract](https://pgboss.io/api/jobs#redrivename-options), [direct retry](https://pgboss.io/api/jobs#retryname-id-options) | **Documented.** Required PoC: exhaustion → DLQ provenance → redrive and assert new-id/reset/config semantics. This differs from a contract that preserves original id or per-job retry overrides. |
| 6. Cron timezone / DST | `schedule(name, cron, data, { tz, key, ...sendOptions })` defaults `tz` to UTC and rejects an unknown zone at schedule time. It evaluates schedules every 30 seconds by default, uses clock-skew offsetting, and uses throttling so multiple instances send one job. Upstream delegates cron interpretation to `cron-parser`. [scheduling API](https://pgboss.io/api/scheduling#schedulename-cron-data-options), [schedule coordination](https://pgboss.io/api/scheduling) | **Timezone validation and multi-instance de-duplication documented; DST/misfire policy unverified.** Required PoC must cover a DST spring gap and fall repeated local time using a named IANA zone, plus StoreWeave's required missed-schedule policy. pg-boss documentation does not state whether each ambiguous local occurrence is emitted, nor skip/catch-up policy during downtime. |
| 7. Queue schema upgrades | `start()` automatically installs/migrates internal storage by default under transaction-scoped advisory locks; `schemaVersion()` observes it. For manual operation, use `getMigrationPlans(schema, version)`; `getRollbackPlans` exists. `getBamStatus()`/`getBamEntries()` expose asynchronous index migration work, and `detectSchemaDrift()` reports but does not repair drift. [start/schema APIs](https://pgboss.io/api/ops#start), [migration utilities](https://pgboss.io/api/utils), [BAM/drift operations](https://pgboss.io/api/ops#getbamstatus) | **Documented.** The pinned test is **12.29.0 schema 39 → 12.30.0 schema 40**: v40 adds monitor-claim metadata and replaces the fetch index; partitioned queues perform build-before-retire concurrent index work through BAM. [v39/v40 source](https://github.com/timgit/pg-boss/blob/12.30.0/src/migrationStore.ts#L1533-L1593) Required real PG17 PoC: upgrade a schema containing queued, active/retry, failed/DLQ, completed, and partitioned-queue rows; assert version 40, no unfinished BAM entries, `detectSchemaDrift().ok`, and post-upgrade processing. |

## Minimum isolated PoC gates

These are test requirements, not implementation instructions. Keep the packages and PG17 schema isolated from the repository runtime and do not let an old and new dispatcher consume the same jobs.

1. Install exact `12.29.0` in the isolated package, create the isolated schema and representative queue/job states, then stop every old worker.
2. Run exact `12.30.0` against that same isolated schema on **PostgreSQL 17**; record `schemaVersion()` as 39 before and 40 after, wait for `getBamStatus()` to show no non-completed work, then record `detectSchemaDrift()`.
3. In the same matrix, run the six behavioural probes above: Drizzle rollback/commit, returned dedupe identity, active replacement, crash/late completion, DLQ redrive, and named-zone DST occurrences.
4. Capture the lockfile's resolved runtime versions and licenses. No compatibility claim should be promoted from upstream's generic PostgreSQL statement to StoreWeave PG17/Node 22.17.1 until this matrix passes.

## Decision-relevant gaps

- pg-boss documents a PostgreSQL backend, not a PostgreSQL 17 certification; its upstream CI's floating image cannot close that gap.
- `send()` returns `null`, not an existing identity, on rejected singleton/throttled submissions; active replacement is expressly outside `update()`/`upsert()`.
- Lease recovery is retry-based. The required fencing/late-completion behaviour and application idempotency boundary need the real-PG17 PoC.
- `tz` is validated, but DST ambiguity and downtime misfire semantics are not specified in official pg-boss documentation; B05 must define them even if pg-boss is selected.
