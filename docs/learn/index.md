# 動手學 StoreWeave

**想自己從頭開發，沒有要套用購物或現有文章功能？** 請走[從零開發自己的產品](from-zero/index.md)：用獨立 Notes 模組，串起資料表、頁面、權限與 Release，並執行完整範例。
本頁以下保留「先使用既有 Content，再學擴充」的快速路線。

你不必先讀完架構，才能開始使用 StoreWeave。這條學習路徑以 **做出一個能發布文章的網站** 為目標，先使用現有功能，再學會擴充。

讀完並完成操作後，你應該能啟動 Base 網站、建立與發布文章，並判斷下一個需求該用設定、Theme、模組還是 Extension。
範例使用本機練習環境，不需要付款服務或外部整合帳號。

## 先知道你會做出什麼

第一版 Blog 使用現有 Content 模組的 `journal` 文章：有標題、摘要、段落、草稿與發布狀態，以及 `/journal` 列表和文章內頁。
這是教學的可操作範圍。留言、標籤、多作者審稿等進階需求留到第三課拆解，不能當成已經內建。

本路徑選 **Base Release**：它組裝網站設定、內容與認證能力，不要求購物車或訂單。
Base 沒有 Commerce 的管理後台，所以第二課用 API 操作文章。你會看到每個請求的輸入，以及前台隨狀態改變的結果。

依據：[Base 組裝](../../packages/releases/base/src/runtime.ts)、[文章模組](../../packages/platform/content/src/module.ts)、[文章頁面](../../packages/platform/content/src/pages.ts)。

## 第一課：把專案跑起來

先準備工具、設定本機環境，再啟動網站與 Worker。這課也說明設定檔、資料庫與 Release 之間的關係。

**完成條件：** 能開啟首頁、確認服務健康，並準備好下一課的 API 存取方式。

[開始第一課：啟動你的第一個網站 →](getting-started.md)

## 第二課：發布你的第一篇 Blog

用同一篇文章走過完整生命週期。每完成一個寫入，就回到公開頁面確認讀者實際看見什麼。

**完成條件：** 草稿不公開；發布後能從列表進入內頁；下架後公開頁面不再提供文章。

[開始第二課：用現有功能打造 Blog →](build-a-blog.md)

## 第三課：把自己的需求接上來

從「我要換文章版面」「我要加留言」「我要同步到外部服務」三種需求開始，辨認各自的資料與規則由誰擁有。
接著沿既有的完整模組範例，練習把需求拆成輸入、權限、狀態、頁面與驗證。

**完成條件：** 能為自己的第一個延伸功能列出實作位置、既有能力、需要新增的部分，以及一條成功和一條失敗的驗證流程。

[開始第三課：從 Blog 延伸自己的功能 →](extending-a-feature.md)

## 第四課：親手寫一個 Extension

在記憶體測試環境寫一個文章發布紀錄器：宣告 Extension、訂閱真實的發布事件，再驗證它只處理 Blog 文章，並能接受相同事件重送。
這課不需要外部服務，也不會改動前兩課的資料庫。

**完成條件：** 能執行自己建立的測試，並解釋「handler 測試通過」和「Extension 已裝到網站」之間還缺哪些步驟。

[開始第四課：動手寫第一個 Extension →](extension-lab.md)

## 每一課怎麼讀

先讀目標與前置條件，再操作。看到「預期結果」時，先確認自己的畫面或回應吻合，再往下走。
遇到失敗先看該課的排錯段落，不要連續重跑寫入指令來碰運氣。

文中的操作步驟以目前程式與既有測試為依據；文件建置通過不等於你的本機環境已完成操作。
第三課的留言與外部同步屬於設計練習，會明確標出尚待實作的範圍。

::: tip 用可觀察的結果檢查理解
「我讀完了」和「我能做出來」不同。第二課結束後，試著不看範例建立另一篇文章，向另一個瀏覽器視窗證明草稿不會外洩。
:::
