# 從零開發自己的 StoreWeave 應用

你會寫 TypeScript，現在想用 StoreWeave 做自己的產品。這條路線從一個小需求開始：**作者建立短筆記，確認內容後發布，訪客只能讀取已發布的筆記。** 你會親手追讀並修改 Notes 範例，掌握資料、規則、頁面與產品組裝的實際位置。

這裡的「從零」指的是自己定義產品能力。資料庫連線、登入、授權檢查與請求執行機制沿用平台；筆記的資料表、輸入契約、發布條件與公開查詢由 Notes 擁有。完成後，你應該能把同樣的方法用在自己的第一個功能。

## 先選符合目的的路線

| 你想完成什麼 | 從哪裡開始 |
| --- | --- |
| 使用現有文章功能，把網站跑起來並發布 Blog | [使用現有功能的學習路線](../index.md) |
| 自己定義資料、規則與頁面，學會組裝一個應用 | **本路線：從零開發 Notes** |
| 已經熟悉基本流程，要接上傳、背景工作與通知 | [完整模組開發範例](../../module-development.md) |

Notes 使用自己的 Product Module 與 Release，選用網站設定和認證等共用能力；它沒有選入 Content 或 Commerce。即使功能也叫「發布」，你仍會看到自己的資料表與 handler，而非呼叫現成的文章 API。

## 開始前需要什麼

你需要能閱讀 TypeScript 的物件、函式、`async`／`await` 與 `import`，並知道 SQL 資料表和 HTTP 請求的基本用途。第一次遇到 Zod、Drizzle 或 StoreWeave 術語時，可以沿教材中的檔案定位理解，不必先讀完整個框架。

請在倉庫根目錄操作。主機開發需要 Node.js 22 以上，以及 [package.json](../../../package.json) 的 `packageManager` 指定版本 pnpm；先執行 `pnpm install` 安裝既有依賴。需要資料庫的步驟與整合測試還需要正在執行的 Docker。

本路線使用獨立的本機練習資料庫。具體建置、啟動和環境設定在第三課提供，讀到該課再建立環境。發布筆記是應用內的狀態轉換；最後一課的建置則產生交付物，兩件事分開驗證。

## 五課做出一條完整流程

每一課都先說明要解決的問題，再定位程式、動手操作，最後以可觀察的結果檢查。請依序進行：上一課留下的資料契約，會成為下一課頁面的輸入。

| 課程 | 要動手完成的事 | 完成時應能證明什麼 |
| --- | --- | --- |
| [1. 平台給了什麼，我要寫什麼](platform-map.md) | 從模組宣告追到寫入、讀取與頁面，再找 Release 組裝入口 | 指出哪個檔案擁有筆記規則，哪個檔案選取模組；說明為何新增功能不必修改 kernel |
| [2. 寫出第一個模組](first-module.md) | 建立自己的資料形狀，追讀 migration、Command、Query 和模組註冊 | 能解釋一筆筆記如何落表，並完成課內的小改動與檢查 |
| [3. 接上頁面與 Release](pages-and-release.md) | 把讀寫流程接到頁面與 Theme，建置並啟動 Notes | 能開啟自己的頁面，說明 URL、view、HTML 各由誰決定 |
| [4. 加上權限與發布邊界](permissions-and-publishing.md) | 用作者與訪客兩種身分走過草稿、發布與公開閱讀 | 未授權寫入會被拒絕；公開列表與內頁都無法讀到草稿 |
| [5. 測試、建置與交付](test-and-ship.md) | 驗證成功與失敗情境，檢查 Release 產物與交付條件 | 分清 handler、實際 HTTP、建置產物各自的驗證證據，知道上線前還需完成哪些檢查 |

## 你會擁有的程式，與沿用的能力

| 你負責的產品決定 | 沿用 StoreWeave 的部分 |
| --- | --- |
| 一筆筆記有什麼欄位、誰擁有它 | 資料庫連線、migration 執行機制 |
| 哪種輸入有效、何時可以發布 | Command／Query 契約與 Bus 執行機制 |
| 作者與訪客可以做哪些事 | Actor、權限註冊與授權檢查；認證能力 |
| 草稿可以在哪裡讀到、公開頁長什麼樣 | 頁面路由與 Theme renderer 的接合機制 |
| 這個應用包含哪些模組與 Theme | Release manifest、target projections 與共用建置工具 |

平台能執行你宣告的檢查，但「訪客看不到草稿」仍要由自己的權限與查詢條件實作，並以測試證明。[第一課](platform-map.md)會把這些責任對回檔案。

## 完成後，試著離開範例

另寫一張小需求，例如「作者可以搜尋自己的草稿」。先列出受影響的輸入、資料條件、權限、頁面與失敗測試，再指出各自應改哪個檔案。能完成這個拆解，才代表你開始掌握自己的模組。

需要查完整契約時，再讀[模組開發](../../module-development.md)；需要理解平台設計時，回到[架構導讀](../../architecture.md)。
